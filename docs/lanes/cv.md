# LANE A — Computer vision & training

**You own:** photo → `inventory.json`. Nothing else. You are measured on one number:
**end-to-end set accuracy on real photos of a real pile.**

**You do not own:** the build model, the validator, the UI. If you find yourself writing either, stop.

**Your contract:** `00-contracts.md` Contract 1. Produce that JSON. How you produce it is entirely
yours, and you may change the method four times without telling anyone.

> Full technical detail is in [`../06-cv-training.md`](../06-cv-training.md). This file is the
> lane plan: order, hours, Lambda runbook, and when to bail.

## The two-path rule

You always have two implementations behind one interface:

```python
# vision/__init__.py
def segment(image) -> list[Mask]:        # VISION_SEG=opencv | model
def classify(crop) -> list[Candidate]:   # VISION_CLS=brickognize | model
```

**Path 1 (classical) must work before Path 2 (trained) is started.** OpenCV segmentation +
Brickognize API gets you a working inventory in ~4 hours with no GPU. That is your floor and it is
never deleted. Path 2 is an upgrade you ship if it beats Path 1 on your eval set, and only then.

Two implementations behind one interface is also a better answer to a judge than one.

## Hour by hour

### T+0 → T+4 — floor first, and launch the renders
- [ ] `vision/segment.py` — OpenCV: LAB background estimate from the border ring → threshold →
      morphology → distance transform + watershed. Controlled background assumed.
- [ ] `vision/classify.py` — Brickognize: `POST api.brickognize.com/predict/parts/`,
      multipart field `query_image`, 8 concurrent, **cached by SHA-256 of the crop bytes**.
- [ ] `vision/color.py` — erode mask 3px, drop top 15% luminance and bottom 10%, median LAB,
      nearest of ~40 common colours, `conf = 1 - d1/d2`.
- [ ] Emit `fixtures/inventory.json` from a real photo. **This unblocks the other two lanes.**
- [ ] **Launch the Lambda render job in the background** (§Lambda runbook). Rendering is wall-clock
      you can't get back — start it while you build the classical path.

### T+4 → T+8 — the eval harness, before any training
- [ ] `eval/real_eval.py` computing the three numbers in `../06-cv-training.md` §4. **Write this
      before you train anything.** A training run with no eval is a slot machine.
- [ ] Shoot the real photos (§Photo shoot below). 1 hour, do it in one block, don't drip-feed it.
- [ ] Label 20–30 pile masks in CVAT or Roboflow. Set a 45-minute timer and stop when it rings.

### T+8 → T+14 — stage 1
- [ ] Train the class-agnostic segmenter on synthetic piles. ~2–3 h wall clock; **do something else
      while it runs** — go help with the inventory UI, don't watch the loss curve.
- [ ] Evaluate on real. If recall < 0.8, the problem is almost always your render distribution
      (no physics piles, wrong backgrounds, too-clean lighting) — **not** the model or the epochs.

### T+14 → T+20 — stage 2
- [ ] 200-way classifier on crops generated by *stage 1's own masks*, not on ideal isolated renders.
- [ ] Fine-tune on the real single-brick photos. This is the few-shot step and it's where most of
      the real-world accuracy comes from.
- [ ] Compare against Brickognize **on the same eval set**. Keep whichever wins. Genuinely — if
      Brickognize wins, that's a result, ship it and say so.

### T+20 → T+26 — the reconciler + hardening
- [ ] Batch reconciliation call (`../01-architecture.md` §6.3) — suggestions only, never auto-apply.
- [ ] Confirm-loop anchoring: one confirmed row re-ranks the ambiguous ones. ~20 lines, looks like magic.
- [ ] Export the winning models to **ONNX** and run inference **locally on the demo laptop**.

### T+26 → T+28 — freeze
- [ ] Both paths working, env-var switchable, both verified offline.

## Lambda runbook

Your total need is **~15–20 GPU-hours ≈ $25 of credits**. Compute is not your constraint; wall
clock is. Plan accordingly — run experiments in parallel rather than serially.

| Job | Instance | Why |
|---|---|---|
| Rendering (BlenderProc, EEVEE) | **A10 ($0.79/hr)** | Blender scene setup is CPU-heavy; a big GPU is wasted. Many cores > many FLOPs here |
| Stage 1 segmenter | **A100 40GB ($1.99/hr)** | 60 epochs on 25k images in ~2h |
| Stage 2 classifier | A10 | 30–45 min |

**Do not touch the 8×H100 nodes.** They're sold as whole 8-GPU bundles at ~$26/hr; leaving one up
overnight while you sleep is most of your credits gone for nothing.

```bash
# on every instance, first thing:
tmux new -s render                 # so an SSH drop doesn't kill an 80-minute render
nvidia-smi                         # confirm you got what you paid for

# the three habits that save your credits:
#  1. write outputs to the persistent filesystem, not the instance SSD
#  2. `terminate` the instance the moment a job ends — set a phone timer as backup
#  3. checkpoint every epoch; assume the instance vanishes
```

**Capacity, not credits, is the risk.** Popular instance types go unavailable. Launch early, and if
your first choice is gone, take the A10 and move on rather than waiting for an A100.

**Demo-time inference runs on the laptop, not on Lambda.** Export ONNX; a small YOLO-seg runs in
~200ms on a laptop CPU. This removes a GPU instance, a network hop and a whole class of demo failure
from your critical path. Keep a Lambda endpoint up as the "cloud path" only if you're chasing the
Baseten prize.

## Photo shoot — one hour, do it in one block

| Type | Count | Labelling | Where |
|---|---|---|---|
| Single bricks, ~6 angles each, white paper | 40 parts × 6 = 240 | **folder name = label**, free | `data/real/single_bricks/<part_id>/` |
| Piles with counted contents | 20 | a `contents.csv` per photo | `data/real/known_piles/` |
| Piles, hand-masked | 20–30 | ~45 min in CVAT | `data/real/labelled_piles/` |

Vary lighting: desk lamp, overhead, window, and **at least one deliberately bad shot** — harsh
shadow, cluttered background. A model that has never seen bad lighting meets it first at the
judging table.

## When to bail

| Signal | Do |
|---|---|
| T+14 and stage 1 recall on real photos < 0.6 | stop training. Ship Brickognize. You lost 6 hours and gained a fallback you'd have built anyway |
| Segmentation fails on real piles (>40% unknown) | tighten the capture UX — plain background, spread them out, scale card — before touching the model |
| Anyone suggests training a 200-class *detector* | no. Two stages. It's in `../06-cv-training.md` §1 |
| T+20 and you're still tuning | freeze whatever you have and go help the demo |

**Baseten** (Tier 2, `../03-prizes-and-demo.md`): serve the trained segmenter on Baseten as the
